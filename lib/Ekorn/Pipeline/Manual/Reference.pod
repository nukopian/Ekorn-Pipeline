=head1 NAME

Ekorn::Pipeline::Manual::Reference - Ekorn::Pipeline reference

=head1 DESCRIPTION

Stages for any function: let the caller finish the job.

A function that hands out values takes a list of I<stages> from its
caller, as its last arguments, and runs each value through them. A
stage can change a value, drop it, or turn it into several. It can
also stop the pipeline early, so the function makes no more values
than its caller wants.

This reference describes every module, function and method, and how a
pipeline behaves, with examples. L<The how-to|Ekorn::Pipeline::Manual::HowTo> shows how to
do common tasks, one recipe at a time. Notes marked B<For stage
authors> are for people writing stages for others;
L<Writing stages|/"Writing stages"> collects them. Each module's POD
says the same more briefly, and is the authority where they differ.

Ekorn::Pipeline needs Perl 5.36 or later. Its version is 0.x, so the
interface may still change before 1.0, but the version number says
when. A release that only fixes or adds moves the last number, as in
v0.1.1. One that changes how stages behave, or drops or renames a
name, moves the middle number, as in v0.2.0. L<Changes|https://metacpan.org/dist/Ekorn-Pipeline/changes>
says what each release changed.

=head1 At a glance

    use v5.36;
    use Ekorn::Pipeline;
    use Ekorn::Pipeline::Stop;                                       # Stop
    use Ekorn::Pipeline::Gather;                                     # gather
    use Ekorn::Pipeline::Stages::Flow qw(:all);                      # take, drop, take_first, take_last, take_single, take_while, drop_while
    use Ekorn::Pipeline::Stages::Batch;                              # batch, collect
    use Ekorn::Pipeline::Stages::Taps qw(:all);                      # peek, count_into, dump_to

    # A pipeline: a list of stages. A stage is a code reference given one
    # value, in $_ and as its argument, returning nothing, one value or
    # several; or another pipeline, standing for its stages.
    my $p = Ekorn::Pipeline->new(
        sub { $_ % 3 ? $_ : () },    # filter: drop multiples of 3
        sub { $_ * 10 },             # map: ten times each
        sub { ($_, -$_) },           # flatMap: each, and its negative
    );

    # Pushed: called with values, it returns what comes out.
    say join ' ', $p->(1 .. 4);    # 10 -10 20 -20 40 -40

    # Pulled: given a source, it hands out the results one per call.
    my $n    = 0;
    my $next = Ekorn::Pipeline->new(sub { $_ * $_ }, take(3))->iterator(sub { ++$n });
    my @squares;
    while (my($square) = $next->()) { push @squares, $square }
    say "@squares";    # 1 4 9

    # A function of your own, taking stages from its caller.
    sub numbers (@stages) { Ekorn::Pipeline->new(@stages)->(1 .. 10) }
    say join ' ', numbers(drop(2), take(3));    # 3 4 5

=head1 Terms

=over 4

=item *

B<Value:> anything a pipeline is given, or a stage returns. C<undef>,
0 and the empty string are values.

=item *

B<Stage:> a code reference, another pipeline, or a part made for
each run. A code reference is called with one value, and returns a
list of values: none, one or several. A pipeline stands for its own
stages (see L<A pipeline as a stage|/"A pipeline as a stage">). A part
made for each run is a gather, a sink, or anything offering a
stage's or a sink's role method (see
L<Delivering parts for Ekorn|/"Delivering parts for Ekorn">).

=item *

B<Pipeline:> a list of stages, made with C<< Ekorn::Pipeline->new >>
or the word C<pipeline>.

=item *

B<Name:> a name a pipeline is kept under, with C<named>, so that
C<pipeline> and C<named> can take it where they take a stage. A name is
in a package, which says whose it is (see
L<Named pipelines|/"Named pipelines">).

=item *

B<Word:> a short function that makes one of Ekorn's types, such as
C<pipeline> or C<source {...}>, from Ekorn::Pipeline::Factories.

=item *

B<Run:> one call of a pipeline with values, or one iterator made
from it. Gathers, sources and sinks are made afresh for each run.

=item *

B<Source:> what an iterator pulls values from: a code reference,
called with nothing, returning the next value or values, or an empty
list when there are no more; or a source made for each run, which is
told when the run ends (see L<Sources|/"Sources: Ekorn::Pipeline::Source">).

=item *

B<Sink:> a part that consumes every value and, when they run out,
gives its result: one value, such as a count, for a sink of one, or a
list, such as every value, for a sink of many. Usually the last
stage, when its result is what the run gives (see
L<Sinks|/"Sinks: Ekorn::Pipeline::Sink">).

=item *

B<Made for a run:> made afresh at the start of each run, by a
set-up block, so that each run has state of its own. Gathers,
sources and sinks are.

=item *

B<Result:> a value that comes out of the last stage.

=item *

B<Stop:> the exception a stage throws to end its run early, with
C<Stop> or C<< Ekorn::Pipeline::Stop->throw >>.

=item *

B<Flush:> what a gather or a sink does when its input runs out:
what it returns goes on through the stages after it. A gather's held
values, a sink's result. v0.2.0 called a gather's flush its I<end
function>.

=item *

B<End:> a function a gather, a source or a sink can have, called
once, when the run has ended, told how.

=item *

B<How a run ended:> C<done>, C<stopped> or C<died>, as each part of
the run sees it from where it stands (see
L<How a run ends|/"How a run ends">).

=back

=head1 Pipelines: Ekorn::Pipeline

    use Ekorn::Pipeline;
    use Ekorn::Pipeline v0.1.3 qw(is_stage);
    use Ekorn::Pipeline v0.3.0 qw(is_sink);

It exports nothing by default, and C<is_stage> and C<is_sink> on
request. C<is_stage> is new in v0.1.3, so ask for that version on the
C<use> line, as above. Without it, C<use Ekorn::Pipeline qw(is_stage)>
compiles under v0.1.2, which has no C<import>, and fails only when
C<is_stage> is called. C<pipeline_in>, C<named> and C<is_sink> are new in
v0.3.0. The word C<pipeline>, which makes a pipeline whose stages can
be names, is in L<Factories|/"Words: Ekorn::Pipeline::Factories">.

A subclass inherits its C<import>, Exporter's, so C<use My::Pipeline;>
imports nothing, and C<use My::Pipeline qw(name)> croaks unless the
subclass exports C<name> itself. Before v0.1.3, a subclass ignored the
list.

=head2 new

    my $p = Ekorn::Pipeline->new(@stages);

Returns a pipeline that runs values through C<@stages>, in order. Each
stage must be something L<is_stage|/"is_stage"> is true for: a code
reference, a pipeline, or a part offering a stage's or a sink's role
method, such as a gather or a sink. Anything else croaks, naming its
position: "Expected stage #2 to be a code reference or a pipeline". A
source croaks too: "Expected stage #2 to be a stage, not a source".

Any code reference will do: an anonymous C<sub>, a reference to a named
one such as C<\&trim>, or a stage made by a function such as
C<take(10)>. So will a stage made with C<gather>, and a sink, usually
last (see L<Sinks|/"Sinks: Ekorn::Pipeline::Sink">).

With no stages, a pipeline returns its values unchanged.

=head2 A pipeline as a stage

You can give C<new> a pipeline wherever it takes a stage. Its stages
are spliced in where it stands:

    my $clean = Ekorn::Pipeline->new(sub { s( \A \s+ | \s+ \z )()xgr }, sub { length ? $_ : () });
    say join '|', Ekorn::Pipeline->new($clean, take(2))->(' a ', '  ', 'b ', 'c');    # a|b

This runs exactly like C<< Ekorn::Pipeline->new($clean->stages, take(2)) >>.
The spliced stages belong to the new pipeline's run, so a C<take>
inside C<$clean> limits the whole run, not each value. Pipelines can be
nested this way to any depth, and a pipeline of a subclass of
Ekorn::Pipeline works too.

The only difference is in error messages. Given C<$clean> itself, a
stage inside it is named by its position in each pipeline: the third
stage of a pipeline given second is C<#2.3>, and three levels down,
C<#1.2.3>. Given C<< $clean->stages >>, it's named by its position in the
combined list: C<#4>, if one stage came before it.

The stages spliced in are whatever the pipeline's L<stages|/"stages">
method returns, so a subclass can override it. If the override returns
a different list, its stages are named by their position in that list.

To run a pipeline on each value separately instead, call it from a
stage, as
L<Calling a pipeline from a stage|/"Calling a pipeline from a stage">
shows.

=head2 Calling a pipeline

    my @results = $p->(@values);
    my $count   = $p->(@values);

A pipeline is an object that can be called as a code reference. Called
with values, it runs each of them through the stages, in order. In
list context it returns the results; in scalar context, how many there
are.

    my $evens = Ekorn::Pipeline->new(sub { $_ % 2 ? () : $_ });
    my @evens = $evens->(1 .. 6);
    my $count = $evens->(1 .. 6);
    say "@evens, $count of them";    # 2 4 6, 3 of them

A pipeline ending in a sink gives the sink's result instead. In list
context, that's the sink's list, or a sink of one's one value. In
scalar context, a sink of one gives its value, and a sink of many its
list as an array reference:

    use Ekorn::Pipeline::Sinks qw(count_items keep_all);

    my $n    = Ekorn::Pipeline->new(count_items)->('a', 'b');
    my $kept = Ekorn::Pipeline->new(keep_all)->('a', 'b');
    say "$n: @$kept";    # 2: a b

Each call is a run. You can call a pipeline as often as you like, even
from inside one of its own stages.

=head2 iterator

    my $next = $p->iterator($source);
    while (my($result) = $next->()) { ... }

Returns an iterator, an object called as a code reference, that hands
out the results one per call, pulling values from C<$source> as they're
needed. C<$source> is a code reference called with no arguments, which
returns the next value, several values, or an empty list when there are
no more; or anything offering C<ekorn_source>, such as a source made for
each run (see L<Sources|/"Sources: Ekorn::Pipeline::Source">), or another
iterator. Given anything else, C<iterator> croaks "Expected a code
reference".

=over 4

=item *

The source is called only when a result is wanted, and only once the
values from its last call have all gone through the stages. A source
reading a file, a socket or a database reads no more than its caller
asks for.

=item *

The closure returns one result per call. Once the results run out,
it returns an empty list, on every call. Read it in list context, as
C<< my($x) = $next->() >>, so that a result of C<undef>, 0 or C<''> isn't
taken for the end.

=item *

Once the source has returned an empty list, or a stage has stopped
the pipeline, the source isn't called again.

=item *

The flushes of gathers and sinks are called once their input runs
out, before the iterator returns an empty list, and the ends as the
run ends (see L<Runs and how they end|/"Runs and how they end">).

=item *

If a stage or a flush dies, the call dies with it, and the iterator
has ended, as a pushed run does. Every call after returns an empty
list. Nothing waiting goes on, no flush is called, and the source
isn't called again; each end is told C<died>. So a flush such as
C<collect>'s never reports on a run that lost values. To skip a bad
value and carry on, catch the error inside the stage, as in the
how-to's "Catch errors in a stage, but not a stop".

=item *

The iterator has methods to read every value still to come, or only
the first, to end the run early, and to say how it ended (see
L<Iterators|/"Iterators: Ekorn::Pipeline::Iterator">).

=back

Each iterator is a run of its own. Two iterators from one pipeline can
be read in turn, and each has its own C<gather> stages:

    my $numbered = Ekorn::Pipeline->new(gather { my $n = 0; sub { ++$n . $_ } });
    my @a = qw(a b);
    my @b = qw(x y);
    my $first  = $numbered->iterator(sub { @a ? shift @a : () });
    my $second = $numbered->iterator(sub { @b ? shift @b : () });
    say join ' ', $first->(), $second->(), $first->(), $second->();    # 1a 1x 2b 2y

A source that returns C<shift @queue // ()> ends at the first C<undef> in
the queue; C<@queue ? shift @queue : ()> doesn't. Read a filehandle in
scalar context, C<< sub { scalar(<$fh>) // () } >>, so that each call reads
one line.

=head2 stages

    my @stages = $p->stages;

Returns the pipeline's stages, in order: a copy, so changing it
changes nothing in the pipeline. A pipeline that was given as a stage
appears as the stages it was made of. In scalar context, it returns how
many there are.

The list can go anywhere stages go: to C<new>, or to a function that
takes stages. Each is one of Ekorn's types, an object called as a code
reference: a code reference given to C<new> comes back as an
Ekorn::Pipeline::Stage of it (see L<Stages and elements|/"Stages and elements">).
So a function that takes only plain code references, testing them with
C<is_coderef> or C<ref>, won't take them; v0.2.0 gave the code references
themselves. To give C<new> the pipeline itself, see
L<A pipeline as a stage|/"A pipeline as a stage">.

    my $clean = Ekorn::Pipeline->new(sub { s( \A \s+ | \s+ \z )()xgr }, sub { length ? $_ : () });
    say join '|', Ekorn::Pipeline->new($clean->stages, take(2))->(' a ', '  ', 'b ', 'c');    # a|b

Either way, the stages run as if they had been written out in full:

=over 4

=item *

A stop in one of them ends the whole run, and the source isn't called
again.

=item *

A C<gather> stage starts afresh on each run, so pipelines that share
it, or use it twice, don't share its state. A plain closure is the
same code reference wherever it goes, so anything it keeps is
shared. Keep state in C<gather> instead.

=item *

A stage that dies is named by its position, as
L<A pipeline as a stage|/"A pipeline as a stage"> describes.

=back

Calling a pipeline from a stage is different: each call is a run of
its own, as
L<Calling a pipeline from a stage|/"Calling a pipeline from a stage">
explains.

=head2 pipeline_in

    Ekorn::Pipeline->pipeline_in($package, @stages)

Returns a new pipeline of its invocant's class, of C<@stages>, each a
code reference, a pipeline, or the name of one, looked up in
C<$package>, as L<Named pipelines|/"Named pipelines"> explains. It's the
only method that reads names, and it's what the word
L<pipeline|/"pipeline"> calls, with its caller's package.

Call it from code the user calls directly, passing the user's package,
as the word does with C<scalar caller>. Code that passes stages
through, such as a function taking stages from its caller, gives them
to C<new>, which reads no names: the user has already turned any names
into pipelines with C<pipeline>, where they wrote them. If C<new> read
names, it would look them up in the package of whatever called it,
which, for a function passing its caller's stages on, isn't the
caller's.

=head2 named

    Ekorn::Pipeline->named(clean => @stages);         # define from stages
    Ekorn::Pipeline->new(@stages)->named('clean');    # name one you have

Names a pipeline, and returns it. On the class, it makes a pipeline of
the stages after the name, which C<pipeline> would take, names included,
looked up in its caller's package, so a pipeline can be defined from
others. A subclass makes one of its own class. On a pipeline, it names that one, and croaks if given
stages after the name.

The name is kept in the caller's package, unless it's qualified, as
L<Named pipelines|/"Named pipelines"> explains. A name is identifiers,
as Perl's, joined by C<::>, such as C<clean>, C<clean_2> or
C<My::Module::clean>.
Anything else croaks: "Expected a name, made of words joined by ::".

A name can't be defined twice, whatever class C<named> is called on.

    use Ekorn::Pipeline::Factories qw(pipeline);

    Ekorn::Pipeline->named(trimmed  => sub { s( \A \s+ | \s+ \z )()xgr });
    Ekorn::Pipeline->named(nonempty => sub { length ? $_ : () });
    Ekorn::Pipeline->named(cleaned  => 'trimmed', 'nonempty');

    say join ',', pipeline('cleaned')->(' a ', '  ', 'b ');    # a,b

=head2 Named pipelines

A named pipeline is kept for the life of the program, in a package,
which says whose name it is. These rules say which pipeline a name
means:

=over 4

=item *

B<A name is kept per package.> C<named> keeps it in the package that
called it, and C<pipeline> and C<named> look it up in the package that
called them, so two modules can each have a C<clean> of their own.

=item *

B<A qualified name is another package's.> C<My::Module::clean> names
C<clean> in My::Module, wherever it's used. Code that names or looks
up pipelines on another package's behalf qualifies them:
C<pipeline("${package}::clean")>.

=item *

B<A name is resolved when the pipeline is made,> not when it runs.
The pipeline it names is spliced in, as a pipeline given to C<new>
is, and its stages are named in messages by their places in each:
C<#1.2>.

=item *

B<A name can't be defined twice.> Defining it again croaks: "A
pipeline named main::clean is already defined", whatever class
C<named> was called on. Naming the same pipeline again, with
C<< $p->named('clean') >>, is no mistake. But C<named> on a class always
makes a new pipeline, even from a single pipeline, so
C<< Ekorn::Pipeline->named(clean => $p) >> twice croaks.

=item *

B<A name can't be removed.> Define each once, as a program or module
loads, not in a sub that may be called again.

=item *

B<A pipeline, once made, keeps what it found.> As a name is looked
up when the pipeline is made, a name defined or overridden later
never changes a pipeline already made.

=item *

**Only C<pipeline_in>, which the word C<pipeline> calls, and C<named>
read names.** C<new> doesn't, and C<is_stage> is false for a string, so
a function finding its stages with C<is_stage> never takes a value
such as C<'clean'> for one.

=back

=head2 is_stage

    use Ekorn::Pipeline v0.1.3 qw(is_stage);

    is_stage($thing)

True if C<$thing> can be used as a stage: a code reference; a pipeline
of Ekorn::Pipeline or a subclass; or an object offering one of the role
methods C<ekorn_stage>, C<ekorn_sink_one> and C<ekorn_sink_many>, such as
a stage made with C<gather>, or a sink. It's the same test L<new|/"new">
uses. It's false for a string, even the name of a pipeline, and for a
source. It's exported on request.

Use it in a function that takes its stages from the end of its
arguments, so that it accepts the same stages C<new> does, pipelines
included. L<Writing functions that take stages|/"Writing functions that take stages">
has an example.

    say join ' ', map { is_stage($_) ? 'yes' : 'no' }
        sub { $_ }, take(1), Ekorn::Pipeline->new, 'x', [];    # yes yes yes no no

=head2 is_sink

    use Ekorn::Pipeline qw(is_sink);

    is_sink($thing)

Returns C<one> if C<$thing> is a sink of one, giving one value, and
C<many> if it's a sink of many, giving a list; for a pipeline, the sink
it ends in, if any. Both are true. It's false for anything else. A sink
is anything offering C<ekorn_sink_one> or C<ekorn_sink_many>. It's
exported on request, and new in v0.3.0.

    say join ' ', map { is_sink($_) || 'no' } count_items, keep_all, sub { $_ };    # one many no

=head2 ending

    Ekorn::Pipeline::ending()

True while a flush runs, and while the values it gave go through the
stages after it, rather than values from the source or the values a
pipeline was called with. It isn't exported.

It's for code that tells its stages more about each value, such as
where it came from. A value from a flush has no such origin.
DBIx::Squirrel, for instance, tells its stages which row a value was
made from, and has no row to give while C<ending> is true.

    my @seen = Ekorn::Pipeline->new(
        collect { scalar @_ },
        sub { Ekorn::Pipeline::ending() ? "count $_" : $_ },
    )->(qw(a b c));
    say "@seen";    # count 3

A pipeline run inside a stage has its own C<ending>. In a pipeline
called from a stage while C<ending> is true, C<ending> is false until
one of the inner pipeline's own flushes is called.

=head2 run_context

    Ekorn::Pipeline::run_context()

Returns the context the run's source gave, if any: the third thing its
C<ekorn_source> returned, such as a statement's column names. It's for
stages that need to know about the values' source, called as they run.
Each run has its own. A pushed run has none, and an iterator used as a
source passes on its own run's. It isn't exported, and is new in
v0.3.0. L<Stages that ask about their run|/"Stages that ask about their run">
has an example.

=head1 Words: Ekorn::Pipeline::Factories

    use Ekorn::Pipeline::Factories qw(pipeline stage gather source generator yield sink_one sink_many);
    use Ekorn::Pipeline::Factories qw(:all);

The words make Ekorn's types, from what you write. Each is a short,
keyword-like function, one line over a class method: syntax, not
behaviour, so it lives here, not in the class it makes. A package
built on Ekorn uses them as they are (see
L<Delivering parts for Ekorn|/"Delivering parts for Ekorn">). Nothing is
exported by default. Each is new in v0.3.0.

=over 4

=item C<pipeline(@stages)>

B<Makes:> a pipeline

B<Its block:> (takes a list)

=item C<stage {...}>

B<Makes:> a Stage

B<Its block:> the stage itself

=item C<gather {...}>

B<Makes:> a Gather

B<Its block:> a set-up, returning the step, and, optionally, the flush and the end

=item C<source {...}>

B<Makes:> a Source

B<Its block:> a set-up, returning the step, and, optionally, the end and a context

=item C<generator {...}>

B<Makes:> a Source

B<Its block:> a block, called once each run, giving every value it passes to C<yield>

=item C<sink_one {...}>

B<Makes:> a Sink of one

B<Its block:> a set-up, returning the step, the flush, giving the result, one value, and, optionally, the end

=item C<sink_many {...}>

B<Makes:> a Sink of many

B<Its block:> the same, its flush giving a list

=back

A word given something other than a block or code reference croaks
"Expected a code reference". Each passes on the messages of the class
it makes.

C<gather {...}> is the same C<gather> that Ekorn::Pipeline::Gather
exports, as it always has, and is described with it (see
L<gather|/"gather">).

=head2 pipeline

    pipeline(@stages)

Returns a new pipeline of C<@stages>, each a code reference, a pipeline,
or the name of one, looked up now, in the package that called
C<pipeline>, unless it's qualified:

    pipeline(sub { uc }, take(5))                # new, from stages
    pipeline('clean')                            # the pipeline named clean
    pipeline('clean', take(5))                   # it, then more
    pipeline('My::Module::clean', sub {...})     # another package's

It's C<< Ekorn::Pipeline->pipeline_in(scalar caller, @stages) >> (see
L<pipeline_in|/"pipeline_in">). A name is looked up when the pipeline is
made, as L<Named pipelines|/"Named pipelines"> explains, so one not
defined croaks then: "No pipeline named main::clean". Anything that
isn't a code reference, a pipeline or a name croaks, naming its
position: "Expected stage #2 to be a code reference, a pipeline or the
name of one".

Being short, it's handy for passing stages as one pipeline, given
last. A function whose values can be code references can't tell them
from stages with C<is_stage>, but it can take a pipeline given last as
its stages, as
L<Writing functions that take stages|/"Writing functions that take stages">
shows.

=head2 stage

    stage { BLOCK }
    stage sub ($row) { ... }

Returns a Stage: the block, called with each value, as any stage is.
It's an object called as a code reference, so it goes wherever a stage
does. To give it a signature, give it a sub. A Stage keeps what it's
given, so C<stage(\&trim)> never changes C<trim> itself.

=head2 source

    source { SET-UP }

Returns a Source made for each run, as
L<Sources|/"Sources: Ekorn::Pipeline::Source"> describes. Its set-up returns
its step, called with nothing, again and again, giving the next value
or values, or an empty list when there are no more; optionally, its
end, told how the run ended; and, optionally, a context for the run,
which its stages ask for with L<run_context|/"run_context">. With a
context but no end, give C<undef> for the end.

    sub up_to ($last) {
        return source {
            my $n = 0;    # this run's
            return sub () { $n < $last ? ++$n : () };
        };
    }

    my $next = Ekorn::Pipeline->new(sub { $_ * 10 })->iterator(up_to(3));
    while (my($n) = $next->()) { say $n }    # 10, 20, 30

Each run counts from 1 again, as the set-up runs at its start. The
source in L<Made for a run|/"Made for a run"> has an end. A source with
nothing to set up or end needs no word: any code reference is a
source.

=head2 generator and yield

    my $pairs = generator {
        for my $x (1 .. 3) {
            for my $y ($x .. 3) { yield [$x, $y] }
        }
    };
    say join ' ', map { "($_->[0],$_->[1])" } Ekorn::Pipeline->new->iterator($pairs)->all;
    # (1,1) (1,2) (1,3) (2,2) (2,3) (3,3)

C<generator> returns a Source giving what its block passes to C<yield>,
as a Python generator does. Perl can't pause a sub at C<yield>, so each
run calls the block once, to its end, and gives every value it yielded
in one step: the block mustn't loop without end, and runs to its end
even when a stage after it takes only some. For a producer without
end, write a C<source {...}> whose step gives a value each call.
C<yield> croaks "Expected yield to be called inside a generator" when
it's called outside one, and a generator read inside another's block
keeps its own.

An empty block, C<generator {}>, reads as an empty hash: write
C<generator { return }>.

=head2 sink_one and sink_many

    sink_one { SET-UP }
    sink_many { SET-UP }

Returns a Sink, made for each run, as
L<Sinks|/"Sinks: Ekorn::Pipeline::Sink"> describes. Its set-up returns its
step, called with each value, whose return is ignored; its flush,
called when its input runs out, giving its result; and, optionally,
its end, told how the run ended. A sink made with C<sink_one> gives one
value; one made with C<sink_many>, a list. Asked for one value, a
pipeline ending in a sink of many gives its list as an array
reference, so write a sink of one value with C<sink_one>.

    my $longest = sink_one {
        my $max;
        return (
            sub ($s) { $max = $s if length $s > length($max // '') },
            sub ()   { $max },
        );
    };

    say Ekorn::Pipeline->new($longest)->(qw(a bbb cc));    # bbb

=head1 How values go through stages

This section describes stages that are code references. A pipeline
given as a stage stands for its stages, and each of them behaves as
described here.

=head2 One value at a time

Each value goes through every stage before the next one starts, as it
would in a C<for> loop. The results come out in order, and each stage
sees the values in order. Nothing is held between stages, except by a
stage that holds values itself, such as C<batch> or C<collect>.

When a stage returns several values, the first goes through the rest
of the stages, then the second, and so on. Only then does the next
value come from the source or the caller:

    my @trace;
    Ekorn::Pipeline->new(
        sub { push @trace, "1:$_"; ("$_.1", "$_.2") },
        sub { push @trace, "2:$_"; $_ },
    )->(qw(a b));
    say "@trace";    # 1:a 2:a.1 2:a.2 1:b 2:b.1 2:b.2

=head2 What a stage is given

A stage is called with one value, both as its only argument and in
C<$_>. It can name the value with a signature, C<sub ($track) { ... }>,
or use C<$_>, C<sub { ... }>.

=over 4

=item *

C<$_> is local to each call. The caller's C<$_> is left alone, and a
stage can call code that uses C<$_> itself.

=item *

The values a pipeline is called with are copied. Assigning to C<$_>
or C<$_[0]> changes the pipeline's copy, not the caller's variable.

=item *

A reference is copied as a reference. A stage that changes the hash
or array it's given changes the caller's.

=back

=over 4

B<For stage authors:> a stage is always called with exactly one
argument, so a one-argument signature is safe. Don't change the
value you're given; return a new value instead. The exception is a
stage whose job, as documented, is to change it.

=back

=head2 What a stage returns

A stage returns a list, and what it returns is all that goes on:

=over 4

=item an empty list

B<Its kind:> a filter

B<What goes on:> nothing: the value is dropped, and the stages after it don't see it

=item one value

B<Its kind:> a map

B<What goes on:> that value, in place of the one it was given

=item several values

B<Its kind:> a flatMap

B<What goes on:> each of them, in order, through the rest of the stages

=back

C<undef>, 0 and C<''> are values, so C<return undef> passes on C<undef>.
A stage ending in a test, such as C<< sub { $_ > 2 } >>, passes on what the
test returns, not the value. To drop a value, return an empty list:
C<return;> or C<()>.

=over 4

B<For stage authors:> a stage run for its side effects, such as
logging, must return the value it was given, as C<peek> does, or the
value is dropped.

=back

=head2 Runs

Each call of a pipeline with values is a run, and so is each iterator
made from it. At the start of each run, the set-up of every gather,
source and sink is called, so what they keep starts afresh (see
L<Made for a run|/"Made for a run">). An
iterator's run starts when the iterator is made, not when it's first
read.

A stage not made with C<gather> is the same code reference on every
run. Whatever it keeps in a closure stays there from one run to the
next:

    my $count = 0;
    my $plain = Ekorn::Pipeline->new(sub { ++$count });
    my @first  = $plain->(qw(a b));
    my @second = $plain->(qw(a b));
    say "@first / @second";    # 1 2 / 3 4

=over 4

B<For stage authors:> put anything a stage keeps, even a count, in
a C<gather> block. A stage made once may be given to several
pipelines, run more than once, or run by two iterators at once.

=back

=head2 Calling a pipeline from a stage

A stage can run a pipeline of its own, so stages can be built from
stages:

    my $trim = Ekorn::Pipeline->new(sub { s( \A \s+ | \s+ \z )()xgr }, sub { length ? $_ : () });
    say join '|', Ekorn::Pipeline->new(sub { $trim->($_) })->(' a ', '  ', 'b ');    # a|b

Each call of the inner pipeline is a run of its own. Its C<gather>
stages start afresh on each value the outer stage is given, and its
flushes and ends are called at the end of each call. A stop in it ends
only that call, not the outer pipeline. To run its stages in the outer
pipeline's run instead, give the pipeline itself as a stage (see
L<A pipeline as a stage|/"A pipeline as a stage">).

=head1 Runs and how they end

A run is one call of a pipeline with values, or one iterator made from
it. Each run has its own state. A part of the pipeline that needs
state, such as a batch it's filling or a file it has open, is made
afresh for each run, and can be told when the run ends, however it
ends, so it can close the file, or commit what it wrote.

=head2 Made for a run

A gather, a source or a sink, made with a L<word|/"Words: Ekorn::Pipeline::Factories">,
has a block that's its B<set-up>. The
set-up runs at the start of each run. It declares whatever the run
needs, with C<my>, and returns closures sharing what it declared:

=over 4

=item *

B<the step,> called with each value (a gather or a sink), or each
time the source is pulled (a source);

=item *

B<the flush,> for a gather or a sink, called once its input runs
out, what it returns going on through the stages after it. A sink's
gives its result, and is required;

=item *

B<the end,> called once, when the run has ended, told how. It's
optional;

=item *

B<a context,> for a source only, and optional: anything its stages
may ask for with L<C<run_context>|/"run_context">.

=back

    use Ekorn::Pipeline::Factories qw(source);

    sub lines_of ($path) {
        return source {
            open my $fh, '<', $path or die "Can't read $path: $!\n";    # this run's
            return (
                sub ()     { my $line = readline $fh; defined $line ? $line : () },
                sub ($how) { close $fh },
            );
        };
    }

Two iterators of the same pipeline each get their own filehandle, from
their own call of the set-up. A plain code reference is never made for
a run: it's the same code, with the same closure, in every run.

=head2 How a run ends

A run ends in one of three ways, and each part's end is told which,
from where the part stands: C<died> if the run died, anywhere, before
it ended; C<stopped> if its input was cut short, by a stop at or after
it, or by the run being ended from outside; and C<done> if its input
ran out, and the run didn't die. A part whose input had run out before
a stop is told C<done>, and so is a sink that stops the run itself. For
the commonest runs:

=over 4

=item ran out of values

B<The source, and the stages up to and including the one that stopped:> C<done>

B<The stages after it:> C<done>

=item was stopped by a stage

B<The source, and the stages up to and including the one that stopped:> C<stopped>, if it still had values to come

B<The stages after it:> C<done>

=item had a stage or an end die

B<The source, and the stages up to and including the one that stopped:> C<died>

B<The stages after it:> C<died>

=back

A stop ends the stream early for what's before it, and normally for
what's after it. So in

    use Ekorn::Pipeline::Sinks qw(count_items);

    my $n = Ekorn::Pipeline->new(take(5), count_items)->iterator(lines_of('setlist.txt'))->();

the file is closed, told C<stopped>, and C<count_items>, after C<take(5)>,
is told C<done>, and gives 5.

=head2 Flushes and ends

A flush, a gather's or a sink's, is called once its input runs out
normally: when the values ran out, after a stop in a stage before it,
or, for a sink, when the sink stopped the run itself. What it returns
goes on through the stages after it, and while it runs, and they do,
L<C<ending>|/"ending"> is true. The flush of a sink of one gives one
value, C<undef> if it has none. It isn't told how the run ended, as the
run hasn't.

An end:

=over 4

=item *

B<always runs, once, when the run has ended,> however it ended, and
is given how, as its argument: C<done>, C<stopped> or C<died>. A run
has ended as soon as nothing in it can still act on a value, so with
a sink last, it ends as the sink's result is ready, and a sink that
commits only when told C<done> commits then, and never for a run that
dies after it;

=item *

B<gives nothing:> what it returns is dropped;

=item *

B<runs in order:> the source's end first, then each stage's, first
stage first, so a source that fails to close is known before any
sink commits.

=back

After a stage dies, every end still runs, told C<died>, and then the
error is thrown again, as it would have been. An end that dies then is
reported as a warning, naming its stage, and the first error is kept.
An end that dies in a run that hadn't died ends the run with its error,
"Pipeline end of stage #2 failed at ...", and the ends after it are
told C<died>.

=head2 Sources: Ekorn::Pipeline::Source

    use Ekorn::Pipeline::Source;

    my $source = Ekorn::Pipeline::Source->new($setup);

Returns a source made afresh for each run by C<$setup>, a code
reference. Anything else croaks "Expected a code reference". The
set-up returns the source's step, and optionally its end and a
context. Its step is called with nothing each time the run wants more
values, and returns the next value or values, or an empty list at the
end. It can also stop the run, with C<Stop>, when it's had enough: the
values its stop carries are its last, and it's told C<done>.

The word L<source|/"source"> makes one from a block. A source goes to
L<iterator|/"iterator">. It isn't a stage, and given to
C<new> as one, it croaks. Called directly, as a code reference, it
croaks "Expected a source to be read through iterator": a run of its
own would never be ended, so what it opened would stay open.

C<< $source->ekorn_source >> calls the set-up for a new run, and returns
what it returns. A run calls it as it starts; you needn't.

=head2 Sinks: Ekorn::Pipeline::Sink

    use Ekorn::Pipeline::Sink;

    my $total = Ekorn::Pipeline::Sink->new_sink_one(sub {
        my $sum = 0;    # this run's
        return (sub ($x) { $sum += $x }, sub () { $sum });
    });

    say scalar Ekorn::Pipeline->new(sub { $_ * 2 }, $total)->(1 .. 4);    # 20
    say scalar $total->(1 .. 4);                                           # 10

A sink consumes every value it's given and, when they run out, gives
its result: one value, such as a count, for a B<sink of one>, made
with C<new_sink_one>, or a list, such as every value, for a B<sink of
many>, made with C<new_sink_many>. Each takes a set-up, a code
reference, and croaks "Expected a code reference" given anything else.
The set-up returns:

=over 4

=item *

the step, called with each value, in C<$_> and as its argument. What
it returns is ignored;

=item *

the flush, called with nothing, once its input runs out, giving the
result. It's required;

=item *

optionally, the end, told how the run ended.

=back

A sink is usually a pipeline's last stage, so that its result is what
a run gives (see L<Calling a pipeline|/"Calling a pipeline">). Anywhere
else, its result goes on through the stages after it. Its step can
stop the run, with C<Stop>, once it has all it wants: it still gives its
result, and is told C<done>.

The words L<sink_one and sink_many|/"sink_one and sink_many"> make them
from a block. A sink can be called as a code reference with values, as a pipeline of
the one sink would be, and gives its result, from a fresh sink of its
set-up each time.

Called on a subclass with an C<ekorn_sink_one> or C<ekorn_sink_many>
method of its own, C<new_sink_one> or C<new_sink_many> makes the
subclass; otherwise, an Ekorn::Pipeline::Sink::One or
Ekorn::Pipeline::Sink::Many. C<< $sink->ekorn_sink_one >>, or
C<ekorn_sink_many>, calls the set-up for a new run; you needn't.

=head2 Iterators: Ekorn::Pipeline::Iterator

An iterator, made by L<iterator|/"iterator">, is one run. Called as a
code reference, C<< $next->() >>, it hands out the next value. It has
methods of its own:

    my @rest  = $next->all;       # every value still to come; read to the end
    my $rest  = $next->all;       # the same, as an array reference
    my $first = $next->first;     # the next value, or undef; then the run ends
    my $one   = $next->single;    # the next value, or undef, warning if there's another; then the run ends
    $next->finish;                # end the run now
    my $how   = $next->ended;     # done, stopped or died, once there's nothing more to come

=over 4

=item *

**C<all>** reads the run to its end, and returns every value still to
come: a list, or, in scalar context, an array reference. Values
already waiting at the end, such as a sink of many's result, it takes
at once.

=item *

**C<first>** returns the next value, or C<undef> if there's none, and
ends the run, as C<finish> does, so nothing more is read, and a source
holding a resource, such as a statement's lock, lets it go.

=item *

**C<single>** does as C<first> does, but pulls one value more to check
there's no other, and warns "Expected only one item, but there were
more" if there is.

=item *

**C<finish>** ends the run now, if it hasn't ended: nothing more is
read, and nothing waiting is handed out. Each end is told how from
where it stands: C<stopped>, if its input hadn't run out. Every call
after returns an empty list.

=item *

**C<ended>** says whether the source was read to its end: nothing
until the iterator has given all it will, been finished or died;
then C<done> if it was, C<stopped> if a stop anywhere, such as
C<take(5)>'s, or C<finish>, cut the reading short, or C<finish> dropped
values still to be handed out, and C<died> if anything died.

=back

An iterator that's dropped before its values run out ends its run when
the last reference to it goes, as C<finish> does:

    my($first) = Ekorn::Pipeline->new(sub { uc })->iterator(lines_of('setlist.txt'))->();
    # the file is closed here, as the iterator has gone

Perl destroys a lexical iterator as soon as it goes out of scope. One
kept until the program ends is destroyed during global destruction,
when the order of destruction isn't guaranteed, so an end mustn't rely
on other objects then.

Each C<< $next->() >> goes through Perl's overloading of C<&{}> to find the
iterator's code. A loop pulling many values can take the code
reference once, and call it directly:

    my $pull = \&$next;    # the iterator's code, found once
    while (my($value) = $pull->()) { ... }

Keep C<$next> while you use C<$pull>: the code reference doesn't keep
the iterator, and an iterator let go ends its run, after which C<$pull>
gives nothing. Over 300,000 values, this saves about 0.03 s.

An iterator is a source too, so it can be given to another pipeline's
C<iterator>. Its values go through the second pipeline's stages, its
run ends when the second run ends, and the second run's stages see its
run's context. It's one run, so it can be a source only once, before
it has handed out everything it will; after, it croaks "Expected a
source with values still to give: an iterator is one run, and this one
is spent".

=head2 Stages and elements

C<new> keeps each code reference it's given as an
B<Ekorn::Pipeline::Stage>, so that every part of a pipeline is one of
Ekorn's types. You needn't make one, but
C<< Ekorn::Pipeline::Stage->new($code) >> does, from a code reference or an
object called as one; C<< $stage->code >> gives back what it was made of.
Called directly, a stage calls its code with what it's given, but
doesn't set C<$_>: only a run does.

Each of Ekorn's types, a pipeline, a stage, a gather, a source, a sink
and an iterator, is an B<Ekorn::Pipeline::Element>: an object called
as a code reference, which holds the closure it's called as, so it's
freed as soon as nothing else holds it. C<< $element->call(@arguments) >>
does what calling it does.

=head1 Stopping a pipeline: Ekorn::Pipeline::Stop

    use Ekorn::Pipeline::Stop;       # Stop
    use Ekorn::Pipeline::Stop ();    # nothing: call Ekorn::Pipeline::Stop->throw

A stop is the exception that ends a run early and quietly.

=head2 Stop

    Stop();
    Stop(@values);

Throws a stop carrying C<@values>, the last values of the stage that
throws it. It's the same as C<< Ekorn::Pipeline::Stop->throw(@values) >>.
It's exported by default.

=head2 throw

    Ekorn::Pipeline::Stop->throw(@values);
    My::Stop->throw(@values);

Throws a stop carrying C<@values>, blessed into the class it's called
on. A subclass of Ekorn::Pipeline::Stop throws a stop of its own
class.

=head2 What a stop does

When a stage throws a stop:

=over 4

=item *

The rest of the stage that threw it doesn't run.

=item *

The results already out are kept: returned by a pushed run, or
already handed out by an iterator.

=item *

The values the stop carries go on through the stages after the one
that threw it, as that stage's last values.

=item *

Nothing else is processed. Values waiting to go through the stages
are dropped: the rest of the values a pipeline was called with, the
rest of what a source returned in one call, and the rest of what a
stage returned as a flatMap. The source isn't called again.

=item *

The flushes of the stages after the one that stopped are called, in
order. They get the values from before the stop, and the values it
carries. The flushes of the stage that stopped, and of the stages
before it, aren't called. Every end is, as the run ends: told
C<stopped> up to the stage that stopped, if its input was cut short,
and C<done> after it (see L<How a run ends|/"How a run ends">).

=back

    my @seen;
    my @out = Ekorn::Pipeline->new(
        sub { push @seen, $_; $_ == 3 ? Stop('three') : $_ },
        sub { uc },
    )->(1 .. 5);
    say "@out; saw @seen";    # 1 2 THREE; saw 1 2 3

A flush can stop the pipeline too. The values its stop carries go on
through the stages after it, and the flushes after it are still
called. An end can't: the run has ended, and a stop there is an error,
"Expected no stop in an end, as the run has ended".

=head2 The stop object

A stop is an array reference, blessed into its class. Its first
element is that class, and the rest are the values it was thrown with:

    eval { Ekorn::Pipeline::Stop->throw(1, 2) };
    say ref $@, ' ', "@{$@}[1 .. $#{$@}]";    # Ekorn::Pipeline::Stop 1 2

As a string, a stop is "Stop used outside a pipeline", with a newline.
That's what a user sees if one is thrown with no pipeline to catch it.

A stop that isn't an array, made without C<throw> (by blessing a hash
into the class, say), still stops the pipeline, but carries nothing.

=head2 Subclasses

A pipeline recognises a stop with C<isa>, so a stop of a subclass of
Ekorn::Pipeline::Stop works in exactly the same way.

=head2 Catching errors in a stage

A stop is an exception, so a stage that catches errors itself, with
C<eval> or C<try>, catches stops too, including stops from stages it
runs, such as C<take>'s. It must throw them again:

    use experimental qw(try);

    my @out = Ekorn::Pipeline->new(sub ($x) {
        try {
            Stop() if $x > 2;
            return 10 / $x;
        }
        catch ($e) {
            die $e if $e isa 'Ekorn::Pipeline::Stop';
            return 'n/a';
        }
    })->(0, 1, 2, 3);
    say "@out";    # n/a 10 5

Test with C<isa 'Ekorn::Pipeline::Stop'>, not with C<ref>, so that a stop
of a subclass is thrown again too.

=head1 Gathering: Ekorn::Pipeline::Gather

    use Ekorn::Pipeline::Gather;       # gather
    use Ekorn::Pipeline::Gather ();    # nothing: call Ekorn::Pipeline::Gather::gather

A plain stage can't tell when the last value has gone by, and whatever
it keeps stays from one run to the next. A stage that gathers values,
to give them in batches or all together, needs both: fresh state on
each run, and a call when its values run out. C<gather> makes such a
stage.

=head2 gather

    my $stage = gather { ...; return ($step, $flush, $end) };
    my $stage = gather { ...; return ($step, $flush) };
    my $stage = gather { ...; return $step };

Returns a stage that a pipeline makes afresh at the start of each run,
by calling the block. Whatever the block declares is fresh on each
run. The block returns:

=over 4

=item *

the step: a code reference, called with each value like any stage,
or a pipeline (see L<A pipeline as the stage|/"A pipeline as the stage">);

=item *

optionally, the flush, called once its input runs out;

=item *

optionally, the end, called once the run has ended, told how (see
L<Flushes and ends|/"Flushes and ends">). Pass C<undef> for the flush
to have only an end.

=back

C<gather> croaks "Expected a code reference" if it's given something
other than a block or code reference. The block is called when a run
starts, not when C<gather> is called: when the pipeline is called with
values, or an iterator is made from it. A block that returns anything
else is reported then, as "Expected stage #%s, made with gather, to
return a code reference or a pipeline, and optionally a flush and an
end".

What C<gather> returns is an Ekorn::Pipeline::Gather, an object that
can go wherever a stage can. Its C<ekorn_stage> method calls the block,
for a new run; a run calls it as it starts, and you needn't.
C<< Ekorn::Pipeline::Gather->new($block) >> makes one as C<gather> does.

    sub running_total () {
        return gather {
            my $total = 0;    # this run's
            return sub ($n) { $total += $n };
        };
    }

    my $p = Ekorn::Pipeline->new(running_total());
    say join ' ', $p->(1, 2, 3);    # 1 3 6
    say join ' ', $p->(1, 2, 3);    # 1 3 6

=head2 The flush

A gather's flush is called with no arguments, and with C<$_> undefined,
once its input runs out. In a pushed run, that's after the last value
has gone through. With an iterator, it's once the source returns an
empty list, or after a stop before it. What it returns goes on through
the stages after its own, just like what a stage returns: nothing, one
value, or several. It's what v0.2.0 called the I<end function>, and a
gather written for v0.2.0 works as it did.

=over 4

=item *

It's called even when no values went by, so a flush can give an
empty result, such as C<[]>, or nothing at all.

=item *

The flushes are called in order, first stage first. What one returns
goes through the stages after it, and their flushes see it, before
the next flush is called. So a C<collect> after a C<batch> gets
C<batch>'s last, short batch.

=item *

After a stop, only the flushes of the stages after the one that
stopped are called (see L<What a stop does|/"What a stop does">).

=item *

While the values a flush returns go through the stages,
L<C<ending>|/"ending"> is true.

=item *

A flush that dies is reported as its stage would be, by the stage's
position.

=back

A gather's end, its third, is told how the run ended, as every end is
(see L<Flushes and ends|/"Flushes and ends">).

    sub average () {
        return gather {
            my($sum, $n) = (0, 0);
            my $stage = sub ($x) { $sum += $x; $n++; return };
            my $end   = sub ()   { $n ? $sum / $n : () };
            return ($stage, $end);
        };
    }

    say Ekorn::Pipeline->new(average())->(2, 4, 9);    # 5
    say scalar Ekorn::Pipeline->new(average())->();    # 0

The second line prints 0, the number of results. With no values, the
flush returns nothing.

=head2 A pipeline as the stage

A pipeline returned by a C<gather> block as its stage has its stages
made for the run in its place, as if they had been given there. A
C<gather> stage inside it is made afresh too, and a stop inside it ends
the whole run. So the block can build a pipeline for each run, or
choose one:

    my $run   = 0;
    my $alter = Ekorn::Pipeline->new(gather {
        Ekorn::Pipeline->new($run++ % 2 ? sub { uc } : sub { lc }, take(2))
    });
    say join ' ', $alter->(qw(A b C));    # a b
    say join ' ', $alter->(qw(A b C));    # A B

The block's flush, if it returns one, is called after the flushes of
the pipeline's own stages, and its end after their ends. A stage inside the pipeline is named in
messages by its position in each, as C<#2.3> for the third stage of the
pipeline returned by stage #2.

=over 4

B<For stage authors:> a stage that holds values should give them
up in its flush, as C<batch> and C<collect> do, so none are lost when
the values run out. Give the flush an empty signature, C<sub ()>.

=back

=head1 pipe and tap: Ekorn::Pipeline::Pipes

    package My::Client;
    use parent 'Ekorn::Pipeline::Pipes';

A parent class that gives its children two methods, C<pipe> and C<tap>.
Each runs the object it's called on through a pipeline of stages. The
first stage is given the object, in C<$_> and as its argument.
DBIx::Squirrel's database and statement handles have the same two
methods.

=head2 pipe

    my @results = $object->pipe(@stages);
    my $first   = $object->pipe(@stages);

Runs the object through a pipeline of C<@stages>, and returns what
comes out of the last stage. The stages are what C<new> takes: code
references and pipelines, not names. To use a named pipeline, pass
C<pipeline('clean')>. In scalar context, it returns the first
result, or C<undef> if there are none. (A pipeline called in scalar
context returns how many there are; C<pipe> doesn't.) With no stages,
it returns the object.

=head2 tap

    $object = $object->tap(@stages);

Runs the object through a pipeline of C<@stages> for their side effects,
and returns the object, whatever the stages return. A chain of method
calls can carry on after it.

    package Counter {
        use parent 'Ekorn::Pipeline::Pipes';
        sub new ($class) { bless {n => 0}, $class }
        sub up ($self) { $self->{n}++; $self }
        sub n ($self) { $self->{n} }
    }

    say Counter->new->up->tap(sub { $_->up })->up->n;    # 3
    say scalar Counter->new->pipe(sub { $_->n + 10 });   # 10

=head1 Canned stages

Stages for any values, whatever they are and wherever they come from,
in three modules. Each is a function that returns a stage. It checks
its arguments when it's called, not on each value, and croaks at the
caller's line if they're wrong. Those that keep state or hold values
are made with C<gather>, so they start afresh on each run.

=over 4

=item C<take($count)>

B<Module:> Flow

B<Passes on:> the first C<$count> values, then stops

B<Exported:> by default

=item C<drop($count)>

B<Module:> Flow

B<Passes on:> all but the first C<$count> values

B<Exported:> by default

=item C<take_first>

B<Module:> Flow

B<Passes on:> the first value, then stops

B<Exported:> on request

=item C<take_last>

B<Module:> Flow

B<Passes on:> at the end, the last value

B<Exported:> on request

=item C<take_single>

B<Module:> Flow

B<Passes on:> the one value; at a second, warns and stops

B<Exported:> on request

=item C<take_while { ... }>

B<Module:> Flow

B<Passes on:> values until the block is false of one, then stops

B<Exported:> on request

=item C<drop_while { ... }>

B<Module:> Flow

B<Passes on:> values from the first the block is false of

B<Exported:> on request

=item C<batch($size)>

B<Module:> Batch

B<Passes on:> array references of C<$size> values, the last shorter

B<Exported:> by default

=item C<collect>

B<Module:> Batch

B<Passes on:> at the end, an array reference of every value

B<Exported:> by default

=item C<collect { ... }>

B<Module:> Batch

B<Passes on:> at the end, what the block makes of every value

B<Exported:> by default

=item C<peek { ... }>

B<Module:> Taps

B<Passes on:> every value, after calling the block with it

B<Exported:> by default

=item C<count_into(\$n)>

B<Module:> Taps

B<Passes on:> every value, counting them into C<$n>

B<Exported:> by default

=item C<dump_to($fh)>

B<Module:> Taps

B<Passes on:> every value, after writing it to C<$fh> or STDERR

B<Exported:> on request

=back

Each module exports its defaults with a plain C<use>, and every stage
it has with C<:all>. To get the defaults and one more, name C<:DEFAULT>
too:

    use Ekorn::Pipeline::Stages::Flow qw(:DEFAULT take_while);

=head2 Ekorn::Pipeline::Stages::Flow

Stages that decide which values go on, by their position or by a
test.

=head3 take

    take($count)

Passes on the first C<$count> values, then stops the pipeline, so an
iterator stops calling its source. The last value it passes on goes
with the stop, so the source isn't asked for one more than is wanted.
If there are fewer values, it passes them all on. C<take(0)> passes on
none, but it still sees one value first, because a stage isn't called
until there is one. With an iterator, the source is called once.

It croaks "Expected a count of 0 or more" if C<$count> isn't a whole
number.

=head3 drop

    drop($count)

Drops the first C<$count> values, and passes on the rest. With C<take>,
it gives a page: C<drop(20), take(10)> passes on the 21st to the 30th.
It croaks "Expected a count of 0 or more" if C<$count> isn't a whole
number.

=head3 take_first

    take_first

Passes on the first value, then stops the pipeline: C<take(1)>.

=head3 take_last

    take_last

Passes on the last value, once there are no more, reading every one to
find it; nothing if there were none. If a stage before it stops the
pipeline, it passes on the last value to reach it.

=head3 take_single

    take_single

Passes on the one value. At a second, it warns "Expected only one item,
but there were more" and stops the pipeline, so the first is all that
goes on: for when one value was meant, and its limit forgotten.

    say join ' ', Ekorn::Pipeline->new(take_last)->(1 .. 9);      # 9
    say join ' ', Ekorn::Pipeline->new(take_single)->(1 .. 9);    # 1, with a warning

=head3 take_while

    take_while { ... }

Passes on values while the block returns true for them, then stops the
pipeline at the first value it returns false for. That value isn't
passed on. The block gets each value in C<$_> and as its argument. It
croaks "Expected a code reference" if it isn't given a block or code
reference.

=head3 drop_while

    drop_while { ... }

Drops values while the block returns true for them, then passes on the
rest, starting with the first value it returns false for. After that,
the block isn't called again on that run. The block gets each value in
C<$_> and as its argument. It croaks "Expected a code reference" if it
isn't given a block or code reference.

    say join ' ', Ekorn::Pipeline->new(drop_while { $_ < 3 }, take_while { $_ < 6 })->(1 .. 9);
    # 3 4 5

=head2 Ekorn::Pipeline::Stages::Batch

Stages that gather values and pass them on together. Both pass on what
they still hold once the values run out.

=head3 batch

    batch($size)

Passes values on in batches of C<$size>, each a new array reference.
Once the values run out, the last batch goes on, which may be shorter.
There's never an empty batch: with no values, there's no batch at all.
It holds no more than one batch at a time. It croaks "Expected a batch
size of 1 or more" if C<$size> isn't a whole number above 0.

=head3 collect

    collect
    collect { ... }

Holds every value. Once they run out, it passes on an array reference
of them. Given a block, it calls the block once, with the values as
its arguments, and passes on what the block returns: nothing, one
value, or several, just like a stage. The block is called even with no
values, so C<collect> always gives a result: an empty array, or what the
block makes of none. It croaks "Expected a code reference" if it's
given something other than a block or code reference.

C<collect> holds every value until the end, so the whole result is in
memory at once.

    say join ' ', map { "[@$_]" } Ekorn::Pipeline->new(batch(2))->(1 .. 5);    # [1 2] [3 4] [5]
    say Ekorn::Pipeline->new(collect { join '+', @_ })->(1 .. 3);               # 1+2+3

=head2 Ekorn::Pipeline::Stages::Taps

Stages that look at each value as it goes by and pass it on unchanged,
for logging, counting or debugging.

=head3 peek

    peek { ... }

Calls the block with each value, in C<$_> and as its argument, and
passes the value on, whatever the block returns. It croaks "Expected a
code reference" if it isn't given a block or code reference.

=head3 count_into

    count_into(\$count)

Counts the values into C<$count>. It sets C<$count> to 0 at the start of
each run, so after a run it holds how many values went by, even if
none did. It croaks "Expected a reference to a scalar" if it isn't
given one.

=head3 dump_to

    dump_to($fh)
    dump_to

Writes each value to C<$fh>, or to STDERR, with Data::Dumper, keys
sorted and indented by two, and passes it on. It croaks "Expected an
open filehandle" if C<$fh> isn't one.

It's for debugging. It writes each value in full, secrets and all. It
doesn't escape control characters in strings, so a value from outside
can send escape sequences to a terminal.

=head1 Errors: Ekorn::Pipeline::Errors

=head2 When a stage dies

A stage, or a flush, that dies with a message is named by its
position, counting from 1 (C<#2.3> for one inside a pipeline given as a
stage). It's reported at the line that ran the pipeline: the call of
the pipeline, or of the iterator that asked for the result. The
message it died with follows, indented by four spaces:

    Pipeline stage #2 failed at app.pl line 12:
        No name for user 7 at app.pl line 9.

An exception object, such as a stop or an object of a class of your
own, is thrown again unchanged, so code that catches it can tell it by
its class.

Either way, the run has ended. Every end is called, told C<died>, and
then the error is thrown again. A pushed run returns nothing. An
iterator returns an empty list on every call after, without calling
its source or any flush again (see L<iterator|/"iterator">).

An end that dies is named the same way, as the end of C<the source> or
of a stage, in "Pipeline end of stage #2 failed at ...". In a run
already dying, it's a warning instead, and the run's own error is
thrown (see L<Flushes and ends|/"Flushes and ends">).

A mistake in making a pipeline, such as a stage that's neither a code
reference nor a pipeline, or in making a canned stage, such as
C<take(-1)>, is reported at the line that made it, before any value goes
through.

=head2 croakf

    use Ekorn::Pipeline::Errors qw(croakf);

    croakf 'Expected a length of 0 or more, not %s', $length;

Croaks with a message made by C<sprintf> from a format and its
arguments, at the line Carp's C<croak> would report: the line that
called the function that called C<croakf>. It's exported only on
request.

It's for modules of stages outside Ekorn::Pipeline too. Called from a
function that makes a stage, it reports a mistake at the line that
called the function, with nothing more to set up. A C<%> in the message
is written C<%%>.

Write the format as a literal in the code. Values go in as arguments,
through C<%s> and the like, never in the format. A format made from
data does whatever its C<%> directives say: C<%999999999s> makes a
string of a gigabyte.

=head2 @INTERNAL and @CARP_NOT

    our @CARP_NOT = @Ekorn::Pipeline::Errors::INTERNAL;

C<@Ekorn::Pipeline::Errors::INTERNAL> lists the packages of
Ekorn::Pipeline. Each of its modules that croaks uses the list as its
C<@CARP_NOT>, so Carp looks past all of them to the first line outside,
in the user's code.

A package that puts the list in its own C<@CARP_NOT> is looked past
too:

=over 4

=item *

B<A module of functions that take stages> runs its callers' stages.
With the list, their errors are reported at its callers' lines, not
at the module's own line that ran the pipeline. DBIx::Squirrel does
this.

=item *

B<A module of stages whose helpers are in another package> puts
that package in its C<@CARP_NOT>, and the helpers' package puts the
module's. Then C<croakf> in a helper reports at the line that called
the module. A helper in the same package needs nothing.

=back

=head1 Writing stages

Write a stage for others the way the canned stages are written, so it
works alongside them.

=over 4

=item *

B<Write a function that makes the stage.> A plain C<sub> is a stage,
but for one others will use, write a function that returns it, as
C<take(10)> does. The function can take options, and check them once,
when it's called, not on each value.

=item *

B<Report mistakes at the caller's line> with C<croakf> (see
L<croakf|/"croakf">), using a literal format and passing the values as
arguments. Start with "Expected" and say what was expected, as the
canned stages do: "Expected a count of 0 or more".

=item *

B<One argument in, a list out.> The stage gets one value, in C<$_>
and as its argument. It returns an empty list to drop it, one value
to pass it on, or several. A stage run for its side effects returns
the value.

=item *

B<Don't change the value you're given,> unless that's the stage's
documented job.

=item *

**Keep state in C<gather>,** even a count, so it starts afresh on each
run and two runs at once don't share it.

=item *

B<Give up held values in a flush.> It's called even when there were
no values, with no arguments and C<$_> undefined.

=item *

B<Close what you open in an end,> which is told how the run ended,
however it ended, rather than in a flush, which isn't called when
the run stops before the stage, or dies.

=item *

B<Stop when no more values are wanted,> with C<Stop>, so an iterator
reads no more. Pass the last value on with the stop, as C<take> does,
so the source isn't asked for one more than is needed.

=item *

B<Throw stops again.> A stage that catches errors should throw a
stop again with C<die $e if $e isa 'Ekorn::Pipeline::Stop';>.

=item *

B<Document what the stage takes and gives:> what kind of value it
expects, what it passes on, whether it holds values or stops, and
what it croaks with.

=item *

B<Names.> A name says what the stage does to a value. A tap's name
says it passes values on, as C<peek> and C<count_into> do. Avoid names
that common modules export: Flow has C<drop>, not C<skip>, because
Test2::V0 and Test::More both export C<skip>. Test2::V0 also exports
names such as C<field>, C<item> and C<call>.

=item *

B<Exports.> Export the stages a module is mostly used for by
default, in C<@EXPORT>. Put the rest in C<@EXPORT_OK>, and all of them
in an C<:all> tag.

=item *

B<Where it goes.> Stages for any values go under
C<Ekorn::Pipeline::Stages::*>. Stages for one kind of value or one
source go under the namespace of the module that knows about it. For
example, DBIx::Squirrel's stages for rows are in
C<DBIx::Squirrel::Stages::Rows>.

=item *

B<Tests.> Calling a pipeline with values tests a stage with nothing
else to set up. Run it twice, to show it starts afresh. Run it with
no values, to show what its flush gives. And run it through an
iterator, counting the source's calls, to show that a stage that
stops reads no more than it should.

=back

    package My::Stages::Numbers {
        use Ekorn::Pipeline::Errors qw(croakf);
        use Ekorn::Pipeline::Gather qw(gather);
        use Ekorn::Pipeline::Stop qw();

        # Pass on values until their sum would pass $limit, then stop.
        sub sum_up_to ($limit) {
            croakf 'Expected a number for the limit, not %s', $limit // 'undef'
                unless defined $limit && $limit =~ m( \A -? \d+ (?: \.\d+ )? \z )xa;
            return gather {
                my $sum = 0;    # this run's
                return sub ($n) {
                    Ekorn::Pipeline::Stop->throw if $sum + $n > $limit;
                    $sum += $n;
                    return $n;
                };
            };
        }
    }

    say join ' ', Ekorn::Pipeline->new(My::Stages::Numbers::sum_up_to(10))->(4, 3, 2, 5, 1);    # 4 3 2

=head1 Writing functions that take stages

=over 4

=item *

B<Take the stages last,> after the function's own arguments, as in
C<sub lines_of ($file, @stages)>. A caller who wants nothing done
passes no stages.

=item *

B<Push what you have; pull what you make.> Call the pipeline with
values already in memory. For values made one at a time, give
C<iterator> a source and return the iterator. Then a stage that stops
saves the work of making the rest.

=item *

B<Let stages do the optional work.> A stage can already filter,
reshape or limit what's returned, so don't add options for it. Keep
the arguments only the function can act on, such as which file to
read.

=item *

B<Say what the first stage is given.> If the function puts stages
of its own before its caller's, say so: error messages count them in
the stages' positions.

=item *

B<Report errors at your callers' lines,> by putting
C<@Ekorn::Pipeline::Errors::INTERNAL> in the module's C<@CARP_NOT>.

=item *

**Find the stages with C<is_stage>,** if the function takes a list
of values of its own before them, so that callers can pass a
pipeline as a stage, as they can to C<new>. The values mustn't be
code references or pipelines themselves, or the last of them would
be taken for stages.

=item *

**Test C<is_stage> before C<is_hashref>,** if the function takes a hash
reference of options before its stages. A pipeline is a blessed hash,
so C<is_hashref> (or C<reftype($x) eq 'HASH'>) is true of it too, and a
pipeline would be taken for the options:
C<is_hashref($x) && !is_stage($x)>. Ref::Util's C<is_plain_hashref>,
false for any blessed hash, avoids it too.

=item *

B<Take a pipeline given last as the stages,> if the function's
values can be code references, so that C<is_stage> can't tell them
from stages. A pipeline is never taken for a value by this rule, and
the caller makes one with C<pipeline>. Without one, there are no
stages.

=back

    use Ekorn::Pipeline v0.1.3 qw(is_stage);

    # The values given, up to the stages at the end, through those stages.
    sub only (@args) {
        my @stages;
        unshift @stages, pop @args while @args && is_stage($args[-1]);
        return Ekorn::Pipeline->new(@stages)->(@args);
    }

    my $evens = Ekorn::Pipeline->new(sub { $_ % 2 ? () : $_ });
    say join ' ', only(1 .. 10, $evens, take(3));    # 2 4 6

    package My::Files {
        use Ekorn::Pipeline;
        our @CARP_NOT = @Ekorn::Pipeline::Errors::INTERNAL;

        # The lines of a file, without their newlines, through the caller's stages.
        sub lines_of ($file, @stages) {
            open my $fh, '<', $file or die "Can't read $file: $!\n";
            return Ekorn::Pipeline->new(sub { s( \n \z )()xr }, @stages)
                ->iterator(sub { scalar(<$fh>) // () });
        }
    }

    my $text = "one\ntwo\nthree\n";
    my $next = My::Files::lines_of(\$text, sub { uc }, take(2));
    my @lines;
    while (my($line) = $next->()) { push @lines, $line }
    say "@lines";    # ONE TWO

    use Ekorn::Pipeline::Factories qw(pipeline);

    # What each callback returns, through the stages given last, as a pipeline.
    sub call_all (@callbacks) {
        my $stages = @callbacks && $callbacks[-1] isa 'Ekorn::Pipeline' ? pop @callbacks : pipeline();
        return $stages->(map { $_->() } @callbacks);
    }

    say join ' ', call_all(sub {1}, sub {2}, sub {3}, pipeline(sub { $_ * 10 }, take(2)));    # 10 20

=head1 Delivering parts for Ekorn

For the author of a package that hands out values, such as
DBIx::Squirrel, or a module reading CSV or JSON. Use Ekorn as it is:
deliver sources, sinks and stages that keep its protocols, and let your
users run them in Ekorn's pipelines, with Ekorn's parts and their own.
Don't subclass Ekorn's classes, or wrap them.

=head2 The protocols

A part of yours says what it can be by its methods. Each is called at
the start of a run, and returns closures sharing that run's state:

=over 4

=item C<ekorn_source>

B<Makes it:> a source, given to C<iterator>

B<Returns:> its step, called with nothing for the next value, or an empty list at the end; optionally its end, told how the run ended; and optionally a context, anything its stages may want to know about this run

=item C<ekorn_stage>

B<Makes it:> a stage with state for the run

B<Returns:> its step, called with each value, returning a list; optionally its flush, called when its input runs out; and optionally its end

=item C<ekorn_sink_one>, C<ekorn_sink_many>

B<Makes it:> a sink, giving one value or a list

B<Returns:> its step, called with each value, its return ignored; its flush, giving the result; and optionally its end

=back

The methods are named for Ekorn, so an object of yours with a method
of its own such as C<as_list> is never taken for a part. One object can
offer C<ekorn_source> and one of the others, as a table can be read from
and written to; offering more than one of C<ekorn_stage>,
C<ekorn_sink_one> and C<ekorn_sink_many> croaks where it's given as a
stage. A plain code reference is a source or a stage, wherever it's
given, with no end. None of these needs your package to load Ekorn.

    package My::Rows;

    sub ekorn_source ($self) {
        my $sth = $self->{sth};
        $sth->execute;                                  # this run's
        return (
            sub ()     { $sth->fetchrow_arrayref // () },
            sub ($how) { $sth->finish },
            {columns => $sth->{NAME}},                  # what stages may ask
        );
    }

=head2 Stages that ask about their run

A stage that needs to know about the values' source asks
L<C<run_context>|/"run_context"> for the context its run's source gave.
Each run has its own, and an iterator used as a source passes on the
context of the run inside it. A pushed run has none.

    sub pluck ($name) {
        return sub ($row) {
            my $columns = Ekorn::Pipeline::run_context()->{columns};
            my($at) = grep { $columns->[$_] eq $name } 0 .. $#$columns;
            return $row->[$at];
        };
    }

=head2 Functions that take stages

A function of yours that runs its own values through its caller's
stages finds them with C<is_stage>, or takes a pipeline given last, and
runs them with C<new>, as any user of Ekorn does (see
L<Writing functions that take stages|/"Writing functions that take stages">):

    sub each_row ($rows, @stages) {
        return Ekorn::Pipeline->new(@stages)->iterator($rows);
    }

=head2 Ekorn's functions, for your users

You can export Ekorn's functions to your users, such as C<Stop> or
C<take>, as they are, with Exporter, so they needn't C<use> two
packages. They're the same functions, so your users can mix yours and
Ekorn's freely.

=head2 Your errors

Put C<@Ekorn::Pipeline::Errors::INTERNAL> in your modules' C<@CARP_NOT>,
so a mistake is reported at your users' lines.

=head1 Diagnostics

Every message Ekorn::Pipeline writes, by module. Each is reported at
the line of the caller's code that caused it.

=head2 Ekorn::Pipeline

=over 4

=item *

B<Expected stage #%d to be a code reference or a pipeline:> a stage
given to C<new> wasn't a code reference or a pipeline. It's also raised
for a
pipeline whose overridden C<stages> method returned something that
isn't a code reference.

=item *

B<Expected stage #%d to be a code reference, a pipeline or the name
of one:> a stage given to C<pipeline_in>, and so to the word
C<pipeline>, or to C<named> after the name,
was none of them. For C<named>, stages are counted from the first
after the name.

=item *

B<No pipeline named %s:> a name given to C<pipeline_in>, and so to
the word C<pipeline>, or to C<named>, isn't defined in that package. The
name is given qualified, so it says which package it was looked up
in. It may be defined in another package, which a qualified name
reaches (see L<Named pipelines|/"Named pipelines">).

=item *

B<A pipeline named %s is already defined:> C<named> was given a name
already defined for another pipeline.

=item *

B<Expected a name, made of words joined by ::> (from C<named>): it was given
something other than a name.

=item *

B<Expected only a name, naming a pipeline you have:> C<named>, on a
pipeline, was given stages after the name.

=item *

B<Expected stage #%d to be a stage, not a source:> a source,
offering C<ekorn_source> and none of a stage's role methods, was given
to C<new> as a stage. Give it to C<iterator> instead.

=item *

B<Expected stage #%d to offer one of ekorn_stage, ekorn_sink_one and
ekorn_sink_many, not %s:> a stage offered more than one of the role
methods, so it couldn't say which it is.

=item *

B<Expected a code reference:> the source given to C<iterator> wasn't
a code reference, or anything offering C<ekorn_source>.

=item *

B<Expected the source to return a code reference, and optionally an
end and a context:> a source's C<ekorn_source> returned something
else. Reported when the run starts.

=item *

B<Expected stage #%s to return a code reference, and optionally a
flush and an end:> a stage's C<ekorn_stage> returned something else.
Reported when the run starts.

=item *

B<Expected sink #%s to return a code reference, a flush, and
optionally an end:> a sink's C<ekorn_sink_one> or C<ekorn_sink_many>
returned something else. Reported when the run starts.

=item *

B<Expected no stop in a set-up, as the run has nothing yet to
stop:> a set-up, or a role method, threw a stop. The ends of the
parts already made are told C<died>.

=item *

B<Expected stage #%s, made with gather, to return a code reference
or a pipeline, and optionally a flush and an end:> the block given
to C<gather> for that stage returned something else. Reported when the
run starts.

=item *

B<Pipeline stage #%s failed at %s line %d:> a stage, or its flush,
died with a message, which follows, indented. An exception object is
thrown again unchanged.

=item *

B<Pipeline end of %s failed at %s line %d:> an end died, in a run
that hadn't died. The message follows, indented, and the end is
named: C<the source>, or a stage, as C<stage #2>. An exception object
is thrown again unchanged.

=item *

B<Expected no stop in an end, as the run has ended:> an end threw
a stop, which is an error like any other there, reported as the
message above.

=item *

B<The end of %s died while the run was already dying: %s:> a
warning: an end died in a run that had died. The run's own error is
thrown, once every end has run.

=back

In these, a stage is named by its position: C<#2> for the second
stage, or C<#2.3> for the third stage of a pipeline given as the second
stage.

=head2 Ekorn::Pipeline::Factories

=over 4

=item *

B<Expected a code reference:> a word was given something other
than a block or code reference.

=item *

B<Expected yield to be called inside a generator:> C<yield> was
called with no generator's block running.

=back

=head2 Ekorn::Pipeline::Source

=over 4

=item *

B<Expected a code reference:> C<new> was given something other than

=item *

B<Expected a source to be read through iterator:> a source was

=back

=head2 Ekorn::Pipeline::Sink

=over 4

=item *

=back

=head2 Ekorn::Pipeline::Stage

=over 4

=item *

B<Expected a code reference:> C<new> was given something other than
a code reference, or one of Ekorn's own types.

=back

=head2 Ekorn::Pipeline::Iterator

=over 4

=item *

B<Expected only one item, but there were more:> a warning: C<single>
found more than one value to come.

=item *

B<Expected a source with values still to give: an iterator is one
run, and this one is spent:> an iterator was given as a source after
it had handed out everything it will, been finished, or died.

=back

=head2 Ekorn::Pipeline::Stop

=over 4

=item *

B<Stop used outside a pipeline:> a stop was thrown with no pipeline
running to catch it.

=back

=head2 Ekorn::Pipeline::Gather

=over 4

=item *

than a block or code reference.

=back

=head2 Canned stages

=over 4

=item *

B<Expected a count of 0 or more:> C<take> or C<drop> was given
something other than a whole number.

=item *

B<Expected a batch size of 1 or more:> C<batch> was given something
other than a whole number above 0.

=item *

B<Expected a code reference:> C<take_while>, C<drop_while>, C<collect>
or C<peek> was given something other than a block or code reference.

=item *

B<Expected only one item, but there were more:> a warning, not an
error: C<take_single> was given a second value, and stopped the
pipeline, passing on only the first.

=item *

B<Expected a reference to a scalar:> C<count_into> was given
something other than a reference to a scalar.

=item *

B<Expected an open filehandle:> C<dump_to> was given something other
than an open filehandle.

=back

=head1 The modules

=over 4

=item C<Ekorn::Pipeline>

Runs values through a list of stages: C<new>, C<pipeline_in>, C<named>, C<iterator>, C<stages>, C<is_stage>, C<is_sink>, C<ending> and C<run_context>.

=item C<Ekorn::Pipeline::Factories>

The words that make Ekorn's types: C<pipeline>, C<stage>, C<gather>, C<source>, C<generator> and C<yield>, C<sink_one>, C<sink_many>.

=item C<Ekorn::Pipeline::Stop>

Ends a pipeline early: C<Stop> and C<throw>.

=item C<Ekorn::Pipeline::Gather>

Makes a stage afresh for each run, with a flush called when its values run out, and an end: C<gather>.

=item C<Ekorn::Pipeline::Source>

A source made afresh for each run, told how it ended: C<new>.

=item C<Ekorn::Pipeline::Sink>

A sink made afresh for each run, giving one value or a list: C<new_sink_one> and C<new_sink_many>.

=item C<Ekorn::Pipeline::Iterator>

One run, handing out its values: C<all>, C<first>, C<single>, C<finish> and C<ended>.

=item C<Ekorn::Pipeline::Stage>

A code reference kept as a stage: C<new> and C<code>.

=item C<Ekorn::Pipeline::Element>

What each of Ekorn's types is: C<call>.

=item C<Ekorn::Pipeline::Pipes>

A parent class giving C<pipe> and C<tap> methods.

=item C<Ekorn::Pipeline::Errors>

Reports errors at the caller's line: C<croakf> and C<@INTERNAL>.

=item C<Ekorn::Pipeline::Stages::Flow>

Canned stages taking or dropping values: C<take>, C<drop>, C<take_first>, C<take_last>, C<take_single>, C<take_while>, C<drop_while>.

=item C<Ekorn::Pipeline::Stages::Batch>

Canned stages gathering values: C<batch>, C<collect>.

=item C<Ekorn::Pipeline::Stages::Taps>

Canned stages run for their side effects: C<peek>, C<count_into>, C<dump_to>.

=back
