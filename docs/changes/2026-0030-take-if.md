# 2026-0030. take_if and drop_if

**Status:** shipped in v0.3.1

**Decisions:** D1 settled: `take_while` and `drop_while` keep their names. D2 settled: `take_if` and `drop_if`, new stages that filter. None open.

**Origin:** roadmap, added 2026-11-13, from Iain: "take_while/drop_while?
I think taken_when or take_if (same for drop...) would read better"

**Started:** 2026-11-13

## Background

Flow had no stage that filters: a filter was written `sub { test ? $_
: () }`, and a stage ending in a test, `sub { $_->{plays} >= 6000 }`,
passes on true or false, not the value, which the user guide lists
among Ekorn's sharp corners.

## Decisions

- [x] **D1.** Should `take_while` and `drop_while` be renamed, as
  `take_if` or `taken_when`? **No,** Iain agreed on 2026-11-13: "while"
  is what says the stage stops at the first value its test fails;
  `take_if` reads as a filter, which `take_while` isn't. They're the
  names Haskell, Python, Rust, Ruby and Java use for the same, and they
  shipped in v0.2.0, which DBIx::Squirrel exports by name.
- [x] **D2.** Should `take_if` and `drop_if` be new stages, filters
  testing every value? **Yes,** Iain agreed on 2026-11-13: they read
  better than `sub { test ? $_ : () }`, take away the sharp corner of a
  test that isn't a filter, and pair with `take`, `drop` and the
  `_while` stages. Not `keep_if`, which would read as one of the `keep`
  sinks, nor `filter` or `grep`, which clash with common names. In
  Flow, exported on request, as `take_while` is.

## The plan

- `take_if` and `drop_if` in Flow, each a Stage, as `take_while` is,
  having no state, so a pipeline of plain subs and them takes the fast
  path (2026-0028). Each croaks "Expected a code reference" given
  anything else.
- Tests in `t/05-stages-flow.t`, and in `t/12-documented.t`'s check
  that each canned stage is an object.
- Flow's POD, the reference, the README, and the user guide: a recipe
  beside `take_while`'s, contrasting the two, and the sharp corner of
  a test that isn't a filter pointing to `take_if`.
- `Changes`, and DBIx-Squirrel told by a message, as it exports Flow's
  stages by name.

Done when both are in, with tests, docs and `Changes`, and
DBIx-Squirrel has its message.

## What happened

Done as planned, on 2026-11-13. The guide's new recipe is checked by
`xt/howto.t`, and the reference's example was run.
